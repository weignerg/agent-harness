# Remote Connections & Headless Client Access Guide

## 1. Executive Summary & Overview

The `agent-harness` architecture provides headless, multi-client connectivity to its local inference stack (**SGLang** on port 30000), unified web frontend (**T3 Code** on port 3773), and orchestrator backend (**OpenCode Server** on port 4096). This architecture enables developers and remote clients to drive autonomous agent workflows from laptops, mobile devices, or remote IDE sessions without consuming GPU VRAM on client machines.

## 2. OpenCode Headless Server (Port 4096)

### 2.1 Service Overview
OpenCode runs as a persistent background user daemon managed by systemd:
- **Systemd Unit**: `opencode-server.service`
- **Default Listening Address**: `0.0.0.0:4096`
- **Environment Configuration**: `~/.config/opencode-backends/env` (mode `0600`)

### 2.2 Security & Authentication
All incoming connections to port 4096 are gated by HTTP Basic Authentication. Credentials are automatically generated and stored in `~/.config/opencode-backends/env`:

```bash
OPENCODE_SERVER_USERNAME=opencode
OPENCODE_SERVER_PASSWORD=<auto-generated-16-char-token>
OPENCODE_SERVER_PORT=4096
OPENCODE_SERVER_HOST=0.0.0.0
```

> [!IMPORTANT]
> The server password is automatically generated during `install.sh` if not already present. Permissions on the configuration file are locked to `0600` (`chmod 0600 ~/.config/opencode-backends/env`) so unprivileged users cannot read stored secrets.

### 2.3 Operational Commands
```bash
# Check service status
systemctl --user status opencode-server

# View live log output
journalctl --user -u opencode-server -f

# Restart the server
systemctl --user restart opencode-server

# Test local endpoint reachability
curl -I http://127.0.0.1:4096/
```

## 3. OpenCode Mobile Client Setup

The **OpenCode Mobile** app provides an interactive mobile development and agent orchestration interface for iOS and Android devices.

- **Upstream Repository**: [https://github.com/alvarolorentedev/opencode-mobile](https://github.com/alvarolorentedev/opencode-mobile)
- **Supported Platforms**: iOS, iPadOS, Android (phone & tablet)

### 3.1 Step-by-Step Mobile Pairing

1. **Verify Network Connectivity**:
   Ensure your mobile device is connected to the same local area network (LAN) as the host server or connected via a secure mesh VPN (such as Tailscale or WireGuard).

2. **Discover Host LAN IP**:
   Find the host IP printed at the conclusion of `install.sh`, or execute:
   ```bash
   # Detect host LAN IP
   ip route get 1 | awk '{print $7; exit}'
   ```

3. **Retrieve Credentials**:
   Inspect your backend credentials:
   ```bash
   grep OPENCODE_SERVER ~/.config/opencode-backends/env
   ```

4. **Configure Mobile Client**:
   - Open **OpenCode Mobile**.
   - Navigate to **Settings** -> **Server Configuration**.
   - Enter **Server URL**: `http://<HOST_LAN_IP>:4096`
   - Enter **Username**: value of `OPENCODE_SERVER_USERNAME` (default: `opencode`)
   - Enter **Password**: value of `OPENCODE_SERVER_PASSWORD`
   - Tap **Connect & Verify**.

5. **Begin Mobile Orchestration**:
   You can now dispatch prompts, inspect active worktrees, view agent plan diffs, and stream tokens directly from your handheld device.

## 4. Antigravity SSH Tunneling & Remote Workspace

For remote workstations running Google Antigravity, VS Code, or Cursor, SSH local port-forwarding provides an encrypted tunnel without exposing unencrypted HTTP traffic over the internet.

### 4.1 SSH Port Forwarding

Establish a background SSH tunnel mapping the host's OpenCode server (port 4096) and SGLang inference engine (port 30000) to your local workstation:

```bash
# Forward OpenCode server (4096) and SGLang (30000)
ssh -N -L 4096:localhost:4096 -L 30000:localhost:30000 user@<HOST_IP_OR_HOSTNAME>
```

To run this as a persistent background session:
```bash
ssh -fN -L 4096:localhost:4096 -L 30000:localhost:30000 user@<HOST_IP_OR_HOSTNAME>
```

### 4.2 Configuring Antigravity Agent MCP & Endpoints

Once tunneled, configure your local client tools to access the forwarded ports:
- **OpenCode Backend**: `http://localhost:4096`
- **SGLang OpenAI Compatible Endpoint**: `http://localhost:30000/v1`
- **MCP Vault Server**: Run directly over SSH or via stdio MCP bridge.

### 4.3 Antigravity Remote Control Server (`agy remote-control start`)

To expose the Antigravity session directly for remote client or browser control without manual port tunnels:

```bash
# Launch Antigravity remote control daemon
agy remote-control start
```

This starts the Antigravity remote control listener, allowing authorized remote clients to attach directly to the running harness session.

## 5. Claude Code Headless & Server Operation

Claude Code can operate in interactive terminal mode, headless CLI mode, or as a background server:

### 5.1 Headless Host Execution
When running inside headless environments (such as terminal multiplexers like `tmux` or `screen`), launch Claude Code with:

```bash
# Non-interactive / headless run inside project directory
claude --print "Explain the architectural boundary between SGLang and OpenCode server"
```

### 5.2 Claude Code Server Daemon (`claude server`)
Claude Code includes a native server mode to process agent commands over local sockets or network bridges:

```bash
# Launch Claude Code server daemon
claude server
```

### 5.3 Environment Variable Pass-Through
Ensure the shell session loads the authoritative backend configuration:

```bash
# Source backend environment configuration
set -a
[ -f ~/.config/opencode-backends/env ] && . ~/.config/opencode-backends/env
set +a
```

## 6. T3 Code (`t3 serve`) Unified Multi-Runtime Frontend

### 6.1 Unified Multi-Runtime Architecture
**T3 Code** provides a web-based and desktop interface (`t3 serve`) operating on port `3773` (`0.0.0.0:3773` or mesh IP). It acts as a single pane of glass uniting all supported agent runtimes:
- **Claude Code**: Direct visibility into `~/.claude/` configurations, slash commands, and active agent sessions.
- **OpenCode**: Integration with `~/.config/opencode/`, MCP servers, and local multi-agent teams.
- **Antigravity (AGY)**: Integration with `~/.gemini/config/plugins/agent-harness` and AGY skill catalogs.
- **Git Worktree Isolation**: Native browsing and switching between isolated worktrees located in `<repo>/.orchestration/worktrees/` (`feat/issue-<n>-*`, `fix/issue-<n>-*`).

### 6.2 Enabling & Managing the Service
The T3 Code frontend is packaged as the systemd user service `opencode-t3-serve.service`.

1. **Installer Configuration**:
   ```bash
   # Enable T3 Code server during installation
   ./install.sh --with-t3

   # Skip T3 Code server deployment
   ./install.sh --no-t3
   ```

2. **Systemd Daemon Control**:
   ```bash
   # Enable and start the service immediately
   systemctl --user enable --now opencode-t3-serve.service

   # Check status and listening port
   systemctl --user status opencode-t3-serve.service

   # Stream live logs
   journalctl --user -u opencode-t3-serve.service -f

   # Stop and disable service
   systemctl --user disable --now opencode-t3-serve.service
   ```

3. **Standalone / Ad-Hoc Invocation**:
   ```bash
   # Run T3 Code serve in foreground
   t3 serve --host 0.0.0.0 --port 3773
   ```

### 6.3 Pairing Desktop, Web & Mobile Clients

1. **Local Area Network (LAN) Web Access**:
   Navigate to `http://<HOST_LAN_IP>:3773` in any modern web browser (Chrome, Edge, Firefox, Safari).

2. **Tailscale & Mesh VPN Access**:
   If running Tailscale or WireGuard, access the frontend securely across networks without opening public router ports:
   `http://<tailscale_node_ip>:3773` or `http://<magicdns_hostname>:3773`

3. **Desktop & Mobile Client Pairing**:
   - In desktop web browsers, install T3 Code as a Progressive Web App (PWA) for desktop launcher integration.
   - On mobile browsers (Safari on iOS, Chrome on Android), add to Home Screen for handheld orchestration alongside OpenCode Mobile.
   - Switch active branches, monitor subagents, and review git diffs within `.orchestration/worktrees/` directly from the UI.

## 7. Default UFW Firewall Configuration

The installer automatically enables host firewall rules by default (`WITH_FIREWALL=true`):

### 7.1 Generated Rules
When enabled, `install.sh` stages firewall rules allowing:
- **SSH (Port 22)**: Allows remote terminal management.
- **OpenCode Server (Port 4096 / 4097)**: Allowed from local subnet (e.g. `192.168.0.0/16` or `10.0.0.0/8`).
- **T3 Code Server (Port 3773)**: Allowed from local subnet and Tailscale mesh for web/mobile UI access.
- **SGLang Inference (Port 30000)**: Bound to `127.0.0.1` locally, inaccessible from external networks unless explicitly tunneled.

### 7.2 Manual Verification and Auditing
```bash
# Check UFW status
sudo ufw status verbose

# Allow OpenCode server and T3 Code frontend from specific subnet
sudo ufw allow from 192.168.1.0/24 to any port 4096 proto tcp comment 'OpenCode LAN access'
sudo ufw allow from 192.168.1.0/24 to any port 3773 proto tcp comment 'T3 Code LAN access'

# Reload rules
sudo ufw reload
```

## 8. Troubleshooting & Diagnostics

| Symptom | Diagnostic Command | Remediation |
|---|---|---|
| OpenCode Server connection refused | `systemctl --user status opencode-server` | Run `systemctl --user start opencode-server` |
| T3 Code Server connection refused | `systemctl --user status opencode-t3-serve` | Run `systemctl --user start opencode-t3-serve` |
| HTTP 401 Unauthorized from Mobile | `grep OPENCODE_SERVER ~/.config/opencode-backends/env` | Re-verify password matching `~/.config/opencode-backends/env` |
| Port 4096 or 3773 unreachable across LAN | `sudo ufw status` | Allow ports 4096/3773 from client subnet in UFW |
| SGLang inference backend unhealthy | `curl http://127.0.0.1:30000/v1/models` | Check `systemctl --user status opencode-sglang*.service` |
| ColBERT reindex timer inactive | `systemctl --user status opencode-colbert-reindex.timer` | Enable timer via `systemctl --user enable --now opencode-colbert-reindex.timer` |
